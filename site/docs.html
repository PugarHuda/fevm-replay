Documentation

fevm-replay is a command-line tool written in Fe. It needs a Linux x86-64 or macOS AArch64 host (on Windows, use WSL), a C compiler, and curl for fetching.

Quickstart

fevm needs std::native::sha256_compress, which reached Fe's master just after the 26.6.0 release, so the project pins Fe at the commit fevm itself pins. Building Fe from source needs Rust 1.99, Node.js and the tree-sitter CLI; cranelift is the native backend.

npm install -g tree-sitter-cli@0.24.7
rustup toolchain install 1.99.0 --profile minimal
cargo +1.99.0 install --locked --root ~/fe \
  --git https://github.com/argotorg/fe \
  --rev 4608e5fdfa3783ec78347f297ad0fced8928fcc7 --features cranelift fe
export PATH="$HOME/fe/bin:$PATH"

git clone https://github.com/PugarHuda/fevm-replay
cd fevm-replay
fe test --backend native .
fe build --backend native -O 2 --emit executable --out-dir out .
./out/fevm_replay fixtures/mainnet/*.json

The last command replays seven saved mainnet transactions and prints MATCH for each.

Commands

CommandWhat it does
fevm_replay <fixture.json>...Replays each single-transaction fixture and prints MATCH or DIFF with every difference. The exit status is the number of fixtures that did not match.
fevm_replay fetch <txhash> <fixture.json> [rpc]Asks the node about one transaction and writes its fixture.
fevm_replay fetch-block <0x-number> <dir> [rpc]Saves the node's answers for a whole block in dir, with five calls plus one per missing delegation target.
fevm_replay block <dir> [<address> <runtime.bin>]Replays every transaction of a saved block. With an address and runtime code, runs a shadow replay.
fevm_replay fetch-code <address> <file> [rpc]Saves the code deployed at an address, as hex.
fevm_replay fuzz <deployed.hex> <port.bin> [runs] [steps] [seed]Random calls against the deployed code and a port, compared after each. Exits 1 if a well-formed call differs.
fevm_replay range <first> <count> <dir> [<address> <runtime.bin>]Fetches the blocks not yet saved under dir, replays them and prints totals. Run it again to resume.

The node needs the debug namespace. The default is the free https://eth.drpc.org; pass another URL as the last argument of fetch or fetch-block. Fetch blocks a few minutes behind the head: near the head, a load-balanced endpoint can answer from nodes that disagree.

Reading the output

DIFF  fixtures/negative/storage.json
  storage 0x…dac17f958d2ee523a2206206994597c13d831ec7 slot 0x03416c29…
    chain 0x…7d44e33f
    fevm  0x…7d44e33e

Each difference names what differs and shows the chain's value above fevm's: status, gas used, a log, an account's balance, nonce or code size, or a storage slot. A block replay labels a difference whose cause it can name:

LabelMeaning
(ran BLOCKHASH…)The transaction read a block hash older than its parent's, which the node's traces cannot carry. Give the fixture a blockHashes object to replay it exactly.
(reads gas after the shadow code ran)Shadow replay only. Other code read the gas left after the port ran, so a cheaper or dearer port may change what it does.
no labelAnything else. In a plain replay, fetch the transaction again with fetch: block traces from load-balanced nodes are sometimes inconsistent. In a shadow replay, the port behaved differently.

block also refuses data whose receipts name a different block hash than the header, and asks you to fetch again.

Fixture format

A fixture is one JSON object holding the node's answers about one transaction, so it replays offline and identically on any machine.

FieldSource
blocketh_getBlockByNumber of the transaction's block
txeth_getTransactionByHash
receipteth_getTransactionReceipt
prestatedebug_traceTransaction with prestateTracer: every account and slot it read
diffThe same tracer with diffMode: what it changed
chainId, blobBaseFeeeth_chainId, and EIP-4844's fee from the block's excess blob gas under mainnet's BPO2 schedule
delegates (optional)Code of EIP-7702 delegation targets the prestate leaves out, from eth_getCode at the parent block
blockHashes (optional)Block numbers to hashes, for BLOCKHASH beyond the parent

Block directories

fetch-block saves the raw JSON-RPC responses: block.json (with full transactions), receipts.json (eth_getBlockReceipts), prestate.json and diff.json (debug_traceBlockByNumber), chain.json, and delegates.json. A mainnet block takes about 22 MB.

Shadow replay

Shadow replay answers one question: does this Fe port behave exactly like the Solidity contract it replaces, on real traffic? For every transaction that touches the address, fevm-replay replaces the code there with the port's runtime code and requires the same logs, balances, nonces and storage as on chain.

(cd ports/weth9 && fe build -O 2 --out-dir ../../out/weth9 .)
./out/fevm_replay range 26394000 20 blocks \
  0xc02aaa39b223fe8d0a0e5c4f27ead9083c756cc2 out/weth9/WETH9.runtime.bin

Gas may differ, and with it what the sender paid and the coinbase earned, so those two balances are settled by the gas difference before comparing. The summary line counts transactions that ran the port, those identical, those that differ only where code read the gas left, and those that behaved differently, and totals the gas on chain and with the port. It then lists the average gas per call of each function of the shadowed contract, on the deployed code and on the port, over the transactions the port left identical (each runs a second time on the deployed code for this).

Code that reads the gas left can legitimately act differently when a port is cheaper: MEV bots that size a builder payment from gas used, and ERC-4337 bundles that record it. A GasWatch tracer detects this, so only a difference without such a reading counts against the port.

Shadow fuzzing

Mainnet only makes the calls it happens to make. fuzz makes the rest: seeded random calls in two copies of one world, one running the deployed code and one running the port, compared after every call (status, return data, logs and all state). Callers include contracts that accept and reject ETH, so withdrawals into fallbacks are exercised.

./out/fevm_replay fetch-code 0xc02aaa39b223fe8d0a0e5c4f27ead9083c756cc2 weth9.hex
./out/fevm_replay fuzz weth9.hex out/weth9/WETH9.runtime.bin 20000 60 1000

Calls are counted in three groups: well-formed, calldata shorter than its arguments, and address arguments with dirty upper bits. Fe's ABI decoder rejects the last two where solc 0.4 lets them through, so only a well-formed difference fails the run. The first difference is printed with its sender, target, value, calldata and the outcome on each side, and the seed and call number replay it.

The call generator targets WETH9's interface. Another contract needs its own selectors in src/fuzz.fe.

Writing a port

ports/weth9 is the worked example. A port is only a drop-in replacement if it keeps the deployed contract's:

  • function selectors and ABI encoding, including return values;
  • event signatures and which arguments are indexed;
  • storage layout, slot for slot. Fe's StorageMap derives keys like a Solidity mapping, and nested maps like nested mappings;
  • fallback behavior and revert data (WETH9 reverts with none);
  • gas passed to calls it makes. WETH9's transfer gives 2,300 gas even when no ETH moves, which is the bug shadow replay found.

Architecture

ModuleRole
src/fetch.feJSON-RPC through curl, started with Spawn; fixtures, block directories, delegation targets, the blob base fee
src/load.feJSON to fevm: load_world, load_tx, load_block, add_extras
src/replay.fereplay_tx: load, fevm::transact, compare. No host capabilities
src/compare.feApplies the chain's diff to the prestate, then compares worlds, receipts and logs in both directions
src/fuzz.feShadow fuzzing: random calls against deployed code and its port, compared after each
src/watch.feGasWatch, an fevm tracer that records GAS after the shadow code ran, and BLOCKHASH
src/lib.feThe command line

Limitations

  • Each transaction runs alone on its own pre-state. Block-level effects such as system contracts and withdrawals are not replayed.
  • Osaka rules and mainnet's BPO2 blob schedule only.
  • fetch-block loads only the parent's block hash. Fetching all 256 costs 86 calls on a free endpoint that allows three requests per batch.
  • The node's traces are the reference, so a node bug shows up as a difference. That has happened, and the chain's own state settled it.
