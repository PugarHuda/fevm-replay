What a certificate checks

  1. Mainnet as it happened. Every transaction of the saved blocks runs on its own pre-state with the port in place of every account holding the deployed code, and must leave the same logs, balances, nonces and storage. Differences where other code read the gas left or a code hash are labeled, and each label is proved from the call tree.
  2. Mainnet, mutated. Each transaction that touched the contract runs again with its calldata changed, or one call into the contract changed in flight, on both codes.
  3. Random calls against both codes in step, including the owner's functions, malformed calldata and dirty addresses.
  4. Mutation testing of the checks themselves: operators changed one at a time in the port's Fe source, built with fe; a check that catches no planted mistake proves nothing.

Any Fe project can run the same checks in CI with the repository's GitHub Action:

- uses: PugarHuda/fevm-replay@main
  with:
    deployed: "0xdac17f958d2ee523a2206206994597c13d831ec7"
    port-dir: ports/usdt
    contract: TetherToken
    token: usdt
    first-block: "26400000"
    blocks: "3"
