What fevm-replay gave back upstream

Running real mainnet traffic through Fe and fevm turns up things their own tests do not. Each item below was reported with a repro from this repository, and two nightly workflows keep checking: one builds fevm-replay against fevm's latest main, the other builds the browser module with Fe's latest commit.

WhereWhatStatus
argotorg/fe#2056The wasm backend kept fevm's tail-call dispatch as plain calls, so a mainnet transaction overflowed the engine's stack, and each handler's frame outgrew the 1 MiB linear-memory stack. We worked around it (a return_call rewrite and a 64 MiB stack), posted a 30-line repro, then the cause: Sonatina's tail_call_sites refused aggregate arguments built in the caller's frame, which is what fevm passes.Fixed in argotorg/fe#2060 (21 Nov). Verified here: built with that commit, without our workarounds and on the default stack, the browser module validates all 93 mainnet blocks, every root, and 20% faster (median 2.03 s a block against 2.55 s).
argotorg/fe#2002Forwarding calldata through MemBuffer cost 40 to 60 gas a call more than solc, measured on the USDC proxy port.Fixed: Call::forward_delegatecall in std, argotorg/fe#2004 (merged 17 Nov)
argotorg/fe#2059std has no way to emit INVALID (0xFE); the USDT and Uniswap V2 pair ports fake it by growing memory until the gas runs out.Open
fe-lang/fevm#26A replay report on 115,000 mainnet transactions, and a request for the operand stack in Tracer::step, to label BALANCE and EXTCODEHASH reads.Became fe-lang/fevm#32 (open)
fe-lang/fevm#33execution-spec-tests v21.0.3 (20 Nov: new trie cases after a reth state root bug, forged block access lists, chain ids over 64 bits). fevm passes all of it; the pull request moves fevm's CI to it.Open

The nightly checks

fevm main: fevm-replay built against fevm's latest commit replays the mainnet fixtures and two proven blocks, every root; a change in fevm that real blocks notice fails the next morning. Fe main wasm: the browser module built with Fe's latest commit and without the #2056 workarounds validates every saved block of the site, and says whether #2056 is fixed. fevm on the newest EEST: fevm's own conformance runner on an execution-spec-tests release newer than the one fevm pins.
