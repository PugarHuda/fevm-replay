Validate a mainnet block in your browser

This runs fevm, the EVM written in Fe, compiled to WebAssembly with fevm-replay's stateless validation (ingots/replay_core): the same Fe code the native tool and CI run. Pick a mainnet block: your browser downloads it, the node's traces of it and its parent's proofs, then fevm proves the parent's state from those proofs, runs the block's system calls and every transaction, and checks every root the header commits to: receipts, transactions, withdrawals, requests, gas, logs bloom and, from the witness and fevm's end state, the state root. Nothing is trusted but the block hash, and for a block near the head a light client checks that against the sync committee's signatures. Every one of the 93 blocks on the stateless page validates in this module, as it does natively.

"Near the head": your browser asks eth.drpc.org for the block, its receipts and its prestate traces, lets the module's witness_keys (the Fe that decides what fetch-proofs fetches natively) say which accounts and slots to prove, asks ethereum-rpc.publicnode.com for those proofs at the parent and at the block, and validates. Then the hash itself: as a light client does (lightclient.mjs), the page starts from one finalized beacon block written in the code, checks each sync committee handoff since (BLS signatures, 2/3 or more of 512), takes the newest header the committee signed and the execution block proven in it, and hashes the headers back to this block. Beacon nodes (publicnode, Lodestar) only supply data. To trust a checkpoint of your own, add &checkpoint=0x… (a finalized beacon block root) to the address. Afterwards you can save what it fetched and check it natively with fevm_replay chain.

fevm runs in a worker, off the page's thread.

How a 4.1 MB module runs a block

The page loads fevm_replay_web.wasm into a Web Worker with Fe's own WebAssembly host, checks it against its build manifest and calls validate_block on one JSON document: the block, its receipts and traces, and the parent's and the block's proofs, as fevm_replay fetch and fetch-proofs saved them. fevm dispatches opcodes with tail calls, each handler calling the next; Fe's WebAssembly backend emits them as plain calls, which overflow the browser's stack within one transaction. web/tailcalls.py turns the 66,142 calls that are in tail position into return_call, in place, and CI checks that the module served here is exactly that build. A tail call frees the engine's stack, but not the module's own: each handler still takes a frame of the stack in linear memory (it passes the cursor by pointer into its caller's frame), so a long stretch of opcodes outgrows Fe's default of 1 MiB. With it, 13 of the 51 stateless blocks validate and 38 trap with unreachable; built with --wasm-stack-size 67108864 (64 MiB), all 51 do, and so do the 42 taken since, with the same verdict as natively, in 0.2 to 12 seconds each (median 2.5; each block's time is on the stateless page).

Verify a mainnet proof

Every stateless block fevm-replay validates starts from eth_getProof answers checked against the parent's state root. That check is Fe (ingots/mpt), with no host capability, so Fe 26.7 compiles the same code to WebAssembly (web/, fe build --backend wasm). Below, your browser runs it on the real proofs of USDT's and USDC's accounts and three of their slots, under the state root of mainnet block 26,424,804. What runs

The page loads fevm_replay_web.wasm, checks it against its build manifest (SHA-256, imports, exports) with the host from Fe's own examples/wasm/host.mjs, hands it the proof as a file and calls its one export, verify. The module hashes every node with keccak256, follows the key's nibbles from the state root to the account's leaf, decodes the account, then does the same from the account's storage root for each slot. Nothing here talks to a node: the proof and the root are the data, and the verdict is Fe's.

The same check, natively: fevm_replay chain proven/0x19335e5 proves 210 accounts and 513 slots of this block's parent this way, then computes the block's own state root from them.
