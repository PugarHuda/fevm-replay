Validate a mainnet block in your browser

This runs fevm, the EVM written in Fe, compiled to WebAssembly with fevm-replay's stateless validation (ingots/replay_core): the same Fe code the native tool and CI run. Pick a mainnet block: your browser downloads it, the node's traces of it and its parent's proofs, then fevm proves the parent's state from those proofs, runs the block's system calls and every transaction, and checks every root the header commits to: receipts, transactions, withdrawals, requests, gas, logs bloom and, from the witness and fevm's end state, the state root. Nothing is trusted but the block hash. Every one of the 51 blocks on the stateless page validates in this module, as it does natively.

Or validate your own block: . It stays in your browser.

fevm runs in a worker, off the page's thread.

How a 3.9 MB module runs a block

The page loads fevm_replay_web.wasm into a Web Worker with Fe's own WebAssembly host, checks it against its build manifest and calls validate_block on one JSON document: the block, its receipts and traces, and the parent's and the block's proofs, as fevm_replay fetch and fetch-proofs saved them. fevm dispatches opcodes with tail calls, each handler calling the next; Fe's WebAssembly backend emits them as plain calls, which overflow the browser's stack within one transaction. web/tailcalls.py turns the 66,146 calls that are in tail position into return_call, in place, and CI checks that the module served here is exactly that build. A tail call frees the engine's stack, but not the module's own: each handler still takes a frame of the stack in linear memory (it passes the cursor by pointer into its caller's frame), so a long stretch of opcodes outgrows Fe's default of 1 MiB. With it, 13 of the 51 stateless blocks validate and 38 trap with unreachable; built with --wasm-stack-size 67108864 (64 MiB), all 51 do, with the same verdict as natively, in 0.3 to 6 seconds each.

Verify a mainnet proof

Every stateless block fevm-replay validates starts from eth_getProof answers checked against the parent's state root. That check is Fe (ingots/mpt), with no host capability, so Fe 26.7 compiles the same code to WebAssembly (web/, fe build --backend wasm). Below, your browser runs it on the real proofs of USDT's and USDC's accounts and three of their slots, under the state root of mainnet block 26,424,804. Change a value and the proof no longer proves it.

What runs

The page loads fevm_replay_web.wasm, checks it against its build manifest (SHA-256, imports, exports) with the host from Fe's own examples/wasm/host.mjs, hands it the proof as a file and calls its one export, verify. The module hashes every node with keccak256, follows the key's nibbles from the state root to the account's leaf, decodes the account, then does the same from the account's storage root for each slot. Nothing here talks to a node: the proof and the root are the data, and the verdict is Fe's.

The same check, natively: fevm_replay chain proven/0x19335e5 proves 210 accounts and 513 slots of this block's parent this way, then computes the block's own state root from them.
