fevm-replay. It replays real Ethereum mainnet history in fevm, the EVM written in Fe, proves the results against the chain's own state roots, and checks Fe ports of Solidity contracts against real traffic.
fevm passes thousands of synthetic tests. But does it run real Ethereum? fevm-replay fetches what each mainnet transaction saw and changed, replays it, and compares everything: status, gas, logs, and every balance, nonce and storage slot. Over a hundred and fifteen thousand transactions so far, and no fevm bug.
Replays used to trust the node that sent the data. Now they don't have to. fetch-proofs saves Merkle proofs of every account and slot a block touched. The chain command checks both header hashes, the pre-state against the parent's state root, and fevm's end state against the block's. Zero differences.
Change one balance by one wei, or one byte of one proof, and the run fails. A clean result now rests on a single block hash. The verifier is written in Fe, using the standard library's R L P and core's Keccak.
Fe functions declare their effects. Only main and the fetcher may start processes or touch files. The function that decides match or diff, and the proof verifier, get a text buffer and nothing else. Calling the network from them is a type error, so a saved block replays the same on any machine.
The blob fee from E I P forty-eight forty-four is a const function, typed with the standard library's units: a timestamp in, wei out. Static asserts run it at compile time against a real block's blob price. Get one wei wrong, and the build fails.
Is a Fe port a drop-in replacement? Ask mainnet. Shadow replay puts the port in place of the deployed contract in every transaction that touches it. Five ports, from five compiler versions: U S D T, every Uniswap V2 pair, wrapped ether, DAI, and U S D C's proxy.
One command, certify, replays two hundred blocks with the port, mutates every transaction, fuzzes it with random calls, and plants mutants in the port's source to score its own checks. Every check passes.
DAI in Fe: over ten thousand mainnet transactions, none behaving differently. Each function points at its handler in the Fe source, found by following the selector through the message and receive blocks.
Where does Fe save gas? Measured opcode by opcode, over six functions of four ports, Fe spends less than solc on stack shuffling, arithmetic and control flow, and more on memory, in every function. That finding went to the Fe compiler team.
Along the way it found three real bugs in the Fe ports, two bugs in node tracers, and the forty-eight transactions the Osaka fork changed. Results were reported upstream to fevm and to the Fe compiler.
Try it without installing Fe: download the release, run the fixtures, and every transaction matches. The code is on GitHub, and the results are at fevm-replay dot vercel dot app.
