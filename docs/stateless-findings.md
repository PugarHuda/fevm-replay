# What 77 mainnet blocks say about stateless Ethereum

*Measured by fevm-replay over 77 mainnet blocks between 26,424,722 and 26,461,900 (16,960 transactions, 2,230 million gas, taken on 5 days: 2026-11-16, 2026-11-17, 2026-11-19, 2026-11-20, 2026-11-21), each one validated statelessly by fevm: every root in its header computed from the parent's witness. The live numbers, with every block, are on the [stateless blocks page](https://fevm-replay.vercel.app/stateless.html). This file is written by [`docs/findings.py`](findings.py) from the page's data.*

*14 of the blocks were taken by the browser's fetcher (`site/wasm/live.mjs`), which picks the smallest non-empty block of the six behind the head to keep the page's download small, and were then validated natively by `chain`; the rest are the block two behind the head, as `follow` takes it. Per-block figures lean a little toward smaller blocks; the 14 blocks hold 1,788 of the 16,960 transactions.*

## How it was measured

For each block, `chain` takes the parent's Merkle proofs (EIP-1186) of every account and slot the block touched as the witness, runs the block's system calls and transactions in fevm, writes fevm's end state into that partial trie and hashes it again; the result is the header's `stateRoot` in every block here. The witness is what that took: the parent's distinct proof nodes, account and storage, plus the few nodes a deletion moved up that the parent's proofs lack. Contract code is counted apart (finding 12): a second run through fevm's own block layer (`fevm::Block`) notes the 31-byte chunks each contract's code runs, as EIP-7864 would carry them. A transaction's witness "alone" is the distinct proof bytes of the accounts and slots it touched, as if it were the only transaction in its block. The binary-tree figures are estimates for EIP-7864's unified tree over the same keys: stems and values exact, stems placed by keccak (the EIP has not fixed its hash), the tree taken to be 28 to 31 levels deep above them.

## Findings

1. **A transaction needs about 16.5 KiB of witness.** Median per block 16.5 KiB, mean 17.5 KiB, from 8.2 to 145.6 KiB. A block needed 0.47 to 8.00 MiB.
2. **What a transaction needs depends on what it does.** Alone in a block, on average:
   - ETH transfer: 10.2 KiB (6,245 transactions, the largest 51.6 KiB)
   - contract call: 47.9 KiB (10,269 transactions, the largest 3224.6 KiB)
   - contract creation: 60.8 KiB (24 transactions, the largest 303.8 KiB)
   - blob transaction: 30.3 KiB (166 transactions, the largest 93.2 KiB)
   - set-code transaction: 58.6 KiB (256 transactions, the largest 316.7 KiB)
3. **Transactions in a block share their witness.** Each on its own, a block's transactions would need 1.99 times the block's witness (median; 1.28 to 2.56): they touch the same tokens, pools and trie nodes near the root.
4. **Per gas, the cost varies about 4-fold.** Median 144 KiB of witness per million gas, from 48 to 215. The busier half of the blocks by gas needs more witness per transaction (16.8 against 16.4 KiB) but less per gas (136 against 151 KiB per million).
5. **Blobs do not weigh on the witness.** Blocks carried 0 to 21 blobs; the half with more needed 14.9 KiB a transaction, the half with fewer 18.2. Blob data never enters the state; a blob transaction's witness is that of the accounts it touches.
6. **Storage is most of the witness: 60.1% of its bytes.** A few contracts carry it: USDT, XEN Crypto, USDC account for 37.4% of all storage witness bytes.
7. **Deep storage tries make each slot expensive.** Nodes on a slot's proof path, on average: USDT 7.4; XEN Crypto 8.2; USDC 7.4; Uniswap v4's PoolManager 6.7; WETH 7.2. That is about 2.0 KiB of witness for every slot a transaction touches in the largest tries.
8. **An account proof is the size EIP-7864 expects.** The account proofs of the heaviest contracts weigh 3,847 bytes (median of 385); the EIP's rationale puts one branch of a hexary tree of 2^32 leaves at 15 × 32 × log16(2^32) = 3,840 bytes ([EIP-7864](https://eips.ethereum.org/EIPS/eip-7864)).
9. **A binary tree would shrink the witness 1.9 to 3.8 times** (median 2.3) on these blocks, less than the 3.75 times the EIP's rationale gives for a single branch (2,880 bytes at 16 children against 768 at 2, for 2^24 leaves): a block's branches share their upper nodes in either tree, and a binary tree also carries each stem and its values. Deep storage tries gain most: XEN Crypto's 23.4 MiB becomes an estimated 7.4 to 8.2 MiB.
10. **But not every contract gains.** A contract with a small storage trie can grow: in the unified tree each of its slots sits on its own path from the root, where its own trie kept them close. 3 of the 40 heaviest contracts grow; 0xb6e6…137a (336 slots, 4.0 nodes a slot) from 68 KiB to an estimated 274 KiB.
11. **eth_getProof is almost a full witness.** A deletion that leaves a branch with one child moves that child up, and the child may belong to a key no transaction touched, which `eth_getProof` cannot name. Such nodes were 1.36% of the nodes and 1.59% of the bytes; they were taken from the block's own proofs, each checked by the hash its parent names. 54 times over the 77 blocks such a node was in neither proof and was taken to be a branch; every state root still matched.
12. **Code is 45% of a full witness, and a block runs a quarter of it.** `eth_getProof` carries no code, but a stateless client needs every contract it runs. A block ran 332 contracts (median) holding 2.9 MiB of code, which a Merkle-Patricia witness carries whole: 18% to 59% of the witness with code added. The 31-byte chunks it ran come to 25% of those bytes (17% to 29%), and EIP-7864 carries only those: with code, the binary tree shrinks the witness 2.0 to 3.3 times (median 2.30). Code read by `CODECOPY` and `EXTCODECOPY` is not counted.
13. **Under EIP-4762 the same blocks would cost 25% more gas.** EIP-4762 (Draft) charges for the witness: per transaction 1,900 a new stem read, 200 a leaf, 3,000 a stem written, 500 a leaf written, 6,200 a leaf filled; it drops EIP-2929's cold charges, EIP-2200's SSTORE costs and the 200 a byte of code deposited. Counted from each transaction's traces and the chunks fevm ran, its charges come to 1.58 times today's for the same accesses and writes: 24.6% of the blocks' gas (median per block 31%, from -10% to 45%). Code chunks, free today, are 49% of the charges and writes 26%. By kind, ETH transfers +27%, contract calls +24%, contract creations +14%, blob transactions +21%, set-code transactions +32% of their gas. An ETH transfer pays 5,810 gas of witness, nearly all for the coinbase it pays its priority fee to (a read and a write of its basic data, 5,600), which the draft does not exempt. Estimates: every touched account counts one basic-data read, and a slot the parent holds as zero counts as filled.

14. **What the draft's choices cost, and who would run out of gas.** Over 77 blocks, the coinbase alone is 6% of EIP-4762's witness charges; exempting it, as the draft exempts the sender and target, takes the increase from 24.6% to 20.4% of the blocks' gas. Sent with the same gas limit, 6,559 of 16,960 transactions (38.7%) would not cover their gas plus the witness charges less today's, and would run out of gas; with the coinbase exempt, 2,451 (14.5%). Wallets that estimate gas before sending would add the margin; contracts and bots that hard-code a gas limit would not. Blocks fill their gas limit 45% today (median) and would fill it 58%; 8 of 77 would not fit their limit as built. Estimates: gas used is after refunds, which a transaction's limit must cover before them, so the shortfall count is a lower bound.

15. **The coinbase exemption would save transfers, not contract calls.** Of 6,245 ETH transfers, 3,644 (58%) would run out of gas under the draft (3,141 transfers were sent with a gas limit of exactly the gas they used); exempt the coinbase and 99 (1.6%) still would. Of 10,269 contract calls, 2,790 (27%) would, and with the coinbase exempt still 2,321 (23%): their shortfall is code chunks and storage, and only 157 were sent with no margin, so the margin wallets add when they estimate gas today would not cover it. Blob transactions: 93 of 166, 0 with the coinbase exempt. Over 77 blocks.

16. **After the coinbase, the price of code decides who runs out of gas.** The same 16,960 transactions, sent with the gas limit they had, under four versions of the charges: the draft as it stands, 38.7% short of gas and +25% gas; the coinbase exempt, 14.5% short of gas and +20% gas; and code chunks at half price, 5.8% short of gas and +4% gas; and code chunks free, 1.4% short of gas and -13% gas. Code chunks are charged per transaction, so a contract call pays again for code the block already ran.

17. **A third of the calls that would still run out of gas go to USDC and USDT.** With the coinbase exempt, 2,321 contract calls over 77 blocks would still run out of gas, sent to 462 contracts. USDC and USDT alone take 793 (34%): calls to them, sent with a tight limit, now pay for the code chunks they run (USDC's proxy and its implementation, USDT's large contract), which cost nothing before. Most calls: USDT 426, USDC 367, 0xfeee…7ffc 100, 0x278d…f8d2 92, 0x51c7…2a7f 77, Uniswap's SwapRouter02 68.

18. **A block access list is 44 times smaller than the witness, and the blocks are about a third serial.** EIP-7928's list, built from each transaction's traces (`ingots/replay_core/src/bal.fe`): 88 KiB a block (median; 9 to 203 KiB), 419 bytes a transaction, RLP uncompressed. With it a client knows each transaction's reads and writes before it runs; the longest chain of transactions each touching what an earlier one wrote is 29% of a block's transactions (median; 18% to 57%), so unlimited cores would need about a third as many steps, and 33% of transactions touch nothing an earlier one wrote. The coinbase, which every transaction credits, is left out, as parallel clients settle fees after the block; the end-of-block index (withdrawals, request bookkeeping) is left out of the size. Over 77 blocks.

## Reproduce

```sh
./out/fevm_replay follow blocks stateless.json 3     # takes, proves and validates 3 head blocks
mkdir proven && tar xzf fixtures/proven/0x19335e5.tar.gz -C proven
./out/fevm_replay chain proven/0x19335e5             # one block: witness, per-kind, heaviest tries
python3 docs/findings.py                             # this file, from the page's data
```

Each block's numbers are in its `summary.json`, written by `chain`; the page's data is [site/data/stateless.json](../site/data/stateless.json).
